# Общий справочник Staffly

Публичный модуль `/guide`, независимый от организаций и авторизации. Данные пользователей,
API организации, выбранная точка и роли текущего аккаунта здесь не используются. Фильтр
аудитории — выбор читателя, а не проверка прав. Ссылки к работе ведут на `/app`, где пользователь
сам выбирает организацию. Не добавлять сюда реальные ID, коды приглашений или персональные данные.

## Где редактировать

- `content/categories.ts` — пять крупных тем навигации (`guideCollections`), их ссылки и девять внутренних тем для группировки статей. Старые адреса тем продолжают работать.
- `content/{start,schedule,time,requests,documents,events,team,organization,account}.ts` — статьи по темам.
- `content/access.ts` — создание кастомных ролей, назначение доступа сотруднику и полный каталог разрешений. Таблицы каталога строятся из `src/app/access/catalog.ts`, без API и данных организации.
- `content/types.ts` — формат статьи и секций, помощники `article`, `section`, `steps`.
- `content/index.ts` — объединение, вводные/рекомендуемые статьи, поиск и ссылки.
- `guide-examples.tsx` — фрагменты настоящих компонентов приложения с локальными вымышленными данными. Они не обращаются к API и не выполняют действия (`inert`).
- `guide-page.tsx` — интерфейс каталога, категории, статьи и увеличения примеров интерфейса.
- `guide.scss` — изолированное оформление справочника: тёмно-синие обложки, синие акценты, номера разделов/шагов и блоки подсказок. Рабочие примеры сохраняют стили приложения.
- `guide-artwork.tsx` — декоративная векторная иллюстрация книги для первого экрана. Не изображает интерфейс приложения; не использовать её как инструкцию.

Статьи — типизированные данные, без JSX и HTML в содержимом. Счётчики, оглавление,
результаты поиска и время чтения вычисляются автоматически. Никакой БД или редактора не требуется.

## Добавление или изменение статьи

1. Найти материал по `slug` в файле темы. `sources` указывает страницы/сервисы, с которыми
   нужно сверять инструкцию. Это редакционная карта, не автоматическая синхронизация с кодом.
2. Сохранить существующие `slug` и `id` секций: на них ведут прямые ссылки и оглавления.
3. Изменить текст, шаги, списки, таблицы, примечания и при необходимости пример интерфейса.
4. Указать `updated: 'YYYY-MM-DD'` после проверки поведения. Для первоначального набора
   используется дата проверки 2026-10-11, заданная в помощнике `article`.
5. Добавить связанные статьи через `related: ['slug']`. Новую статью включить в экспорт
   файла темы; новый файл темы — в `content/index.ts`.
6. При изменении функциональности сайта обновлять соответствующие инструкции и примеры вместе с ним.
7. Выполнить `node --import tsx --test tests/guide.test.ts`, `npm run lint`, `npm run build`.

Пример секции:

```ts
section('find-shift', 'Найдите свою смену', {
  steps: steps(
    ['Откройте расписание', 'Выберите точку и период.'],
    ['Включите фильтр', 'Нажмите «Только мои».'],
  ),
  example: 'schedule',
  note: 'Время показано в часовом поясе точки.',
})
```

`audience`: `everyone` / `manager` / `owner`. Руководительский фильтр показывает
`manager` и `owner`, сотруднику — `everyone`. Все статьи открыты всем читателям.

## Адреса и входы

- `/guide` — каталог; `?q=…&audience=member|manager|owner` — поиск и аудитория.
- `/guide/category/:categoryId` — раздел, с теми же поисковыми параметрами.
- `/guide/:slug#section-id` — статья и постоянная ссылка на шаг/секцию.
- Неверные адреса показывают состояние «Материал не найден» со ссылкой на каталог.
- Входы: неброская текстовая ссылка «Справочник» внизу левого меню, под «Все организации»,
  и подвал публичного сайта. Ссылка слева без рамки, фона и оформления отдельной кнопкой;
  в свёрнутом меню остаётся маленький значок книги с подсказкой. Во всех шапках и верхней
  строке рабочего раздела ссылок/значков справочника нет. Не переносить справочник в шапку.

Поиск локальный, по заголовку, ключевым словам, тексту, таблицам и FAQ. При вводе запроса в разделе поиск охватывает весь справочник; выбранная аудитория продолжает применяться. На странице статьи поле отправляет запрос в общий каталог по Enter или кнопке со стрелкой. В `synonyms`
можно дополнять разговорные варианты запросов. Значения из URL отображаются только как текст.

Оценки, комментарии, предложения тем, аналитика прочтения и административный редактор
намеренно не реализованы. Статьи и примеры обновляются в репозитории.

## Примеры интерфейса

Не добавлять рисованные экраны, похожие на приложение лишь условно, и повторяющиеся обложки.
`example` задаётся только у секции, где фрагмент помогает объяснить действие. Компоненты
`ScheduleAgenda`, `OfferShiftCard`, `WorkTimePanel`, `DocumentRow`, `EventRowContent`, `ReportRules`
используются и в рабочем интерфейсе, и здесь. Их оформление меняется вместе с приложением.
`AccessPermission` из `src/pages/app/access-elements.tsx` — общий презентационный чекбокс
редактора роли и справочника. Пример «Бухгалтер» использует реальные подписи каталога.
Пример ограниченного документа использует `DocumentRow` с вымышленной аудиторией `SELECTED`.
Тексты и данные примеров проверяются вручную при изменении поведения. Не подключать формы
или страницы, которые загружают данные организации, и не использовать реальные данные.

Главная показывает обложку руководства, поиск с быстрыми переходами и пять визуальных карточек тем с количеством инструкций. Все
инструкции сохранены внутри тем и доступны в поиске. Количество вычисляется из контента. Новая статья не требует новой карточки
на главной.

Шапка справочника использует общий `src/component/header/header-frame.tsx` (`HeaderFrame`),
как публичный `Header` и рабочий `AppTopbar`. Логотип, контейнер и адаптивное расположение
общие; варианты `public`, `app`, `workspace` задают оформление, страницы передают свои действия.
Не копировать разметку шапки в новые страницы и не добавлять туда ссылку на справочник.
